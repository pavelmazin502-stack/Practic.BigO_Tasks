# Анализ сложности и производительности

## Сложность структур данных

| Структура | Операция | Сложность |
| :--- | :--- | :--- |
| `DynamicArray` | Доступ по индексу | O(1) |
| `DynamicArray` | Добавление в конец | амортизированная O(1) |
| `DynamicArray` | Удаление по индексу | O(n) |
| `DynamicArray` | Расширение | O(n) |
| `HashTable` | Добавление, поиск, изменение, удаление | в среднем O(1), в худшем O(n) |
| `HashTable` | Расширение (`rehash`) | O(n) |
| `BinaryHeap` | Просмотр следующего (`top`) | O(1) |
| `BinaryHeap` | Добавление и извлечение (`push`, `pop`) | O(log n) |

## Сложность операций ядра

* `create` — **O(log n)** (добавление в массив и хеш-таблицу за O(1), вставка в кучу за O(log n)).
* `get`, `complete`, `fail`, `cancel` — **в среднем O(1)** (поиск индекса в хеш-таблице + доступ к массиву).
* `start-next` — **O(log n)** (извлечение из кучи; отменённые задачи отбрасываются не больше одного раза каждая).
* `list`, `stats` — **O(n)** (проход по всем задачам в массиве).

## Тест на 100 000 задач

Код теста лежит в `tests/bench.cpp`. Запуск:

```bash
g++ -std=c++17 -O2 -Isrc tests/bench.cpp -o build/bench_opt
./build/bench_opt
```

Результаты (100 000 задач с приоритетами 0..100):

| Показатель | Значение |
| :--- | :--- |
| Время добавления 100 000 задач | 28.3213 мс |
| Время 100 000 поисков по ID | 2.02311 мс |
| Время 100 000 извлечений (`start-next`) | 21.9207 мс |
| Количество расширений `HashTable` | 14 |
| Максимальный коэффициент заполнения | 0.749992 |

## Выводы

* Поиск по ID оказался самым быстрым — это подтверждает, что хеш-таблица работает в среднем за O(1).
* Добавление и извлечение работают медленнее поиска из-за бинарной кучи (O(log n) на каждую задачу). Извлечение занимает чуть больше времени, чем добавление, потому что при просеивании вниз делается больше сравнений.
* Хеш-таблица расширялась всего несколько раз за счёт удвоения размера, а коэффициент заполнения не превышал 0.75, поэтому цепочки оставались короткими и поиск не тормозил.
